# CUMCM 论文版式与写作骨架规范

本文件记录团队已经在完整论文中实际调通的公共版式和章节组织。目标是：**下一场比赛直接在现成格式上删改内容，不再重新调字体、标题、图表、公式、伪代码和分页。**

公共格式只在 `feature/paper-shell` 修改；各章节只编辑自己的 `modules/.../paper/*.tex`。终稿还必须检查 `docs/FINAL_PAPER_CHECKLIST.md`。

## 1. 默认全文结构

模板直接编译 `paper/main.tex` 时应看到：

1. 第1页：论文标题 + 摘要；
2. 第2页：目录（可关闭）；
3. 正文从“问题重述”开始重新计第1页；
4. 符号说明；
5. 模型假设；
6. 问题一完整示例；
7. 问题二、问题三只保留一级章节标题；
8. 模型总结与评价；
9. 参考文献另起一页；
10. 附录另起一页；
11. AI使用报告另起一页。

目录开关在 `paper/settings.tex`：

```tex
\showtoctrue
% \showtocfalse
```

不要在章节文件中自行加 `\clearpage` 处理全文分页；公共分页统一由 `paper/main.tex` 管理。

## 2. 字体、页面和正文

- 纸张：A4；
- 页边距：上、下、左、右均 `25 mm`；
- 中文正文：Windows 优先宋体 `SimSun`，无该字体时回退到 Fandol；
- 正文英文和数字：Windows 优先 Times New Roman，无该字体时回退到 TeX Gyre Termes；
- 正文基准字号：小四；
- 行距：`\baselinestretch = 1.38`；
- 段首缩进：`2em`；
- 正文普通段间距：0，不靠空行制造视觉间距。

不要把字体设置散落进章节文件。需要改字体、页边距、标题字号、行距时，只改 `paper/preamble.tex`。

## 3. 标题层级

- 论文题目：三号、加粗、居中；
- 一级标题：中文序号，例如 `一、问题重述`，居中、加粗；
- 二级标题：`4.1` 形式，左对齐、加粗；
- 三级标题：`4.1.1` 形式，左对齐、加粗；
- 目录显示到二级标题。

章节标题不要手打序号，统一使用 `\section`、`\subsection`、`\subsubsection`。

## 4. 摘要

摘要功能结构：

- 总述：1段，约2--3行；
- 每个问题：任务/模型/算法/结果/解释，压缩为约4--6行；
- 末段特点：最多2个真正贯穿全文的亮点；
- 关键词：一般4--6个。

排版上，标题到“摘要”保持紧凑，“摘要”到正文略放开；各问之间保留小段距。模板已经在 `paper/preamble.tex` 固定。

加粗只用于**核心模型、核心算法和最关键结果**，不要整句、整段加粗。场景分析在摘要中直接回答“什么因素影响什么指标”，不要写内部推导过程。

## 5. 每问建议结构

不是每问机械套八个标题，但通常按以下顺序组织：

```text
问题描述与分析
→ 总体流程图
→ 必要的预备工作 / 数据处理
→ 模型建立
→ 模型汇总
→ 模型求解
→ 结果与分析
→ 针对本问主要不确定性的检验
```

其中：

- “问题描述与分析”按“任务对象 → 关键困难 → 建模选择”组织；
- “预备工作”按“数据发现 → 数学量 → 对后续模型的作用”组织；
- 纯文字段落接近五行以上时，优先检查能否分点、分段、公式化或交给图表表达；
- 优化模型要明确决策变量、目标函数、约束和模型汇总；解析推导/直接计算问题不强行构造优化模型。

## 6. 正式表达与术语

正文直接陈述数学事实，避免把团队内部讨论语言带进论文。

- “本文”可用，但不作为每段固定开头；
- 用“统计范围/计算范围”替代模糊的“口径”；
- 用“所有约束满足”“未获得全局整数最优证书”等直接表述替代“严格、证据边界、物理口径”等内部修饰；
- 不使用“机制链、柔性释放/替代、统一链路、层级结构”等只在内部讨论中有意义的词，除非确实是已定义的专业概念。

模型或算法首次出现统一写为：

```text
中文名称（English Full Name，ABBR）
```

附件字段名可以保留英文；正文主动命名的对象不要突然在中文、英文全称和缩写之间跳换。

## 7. 公式与模型汇总

- 普通定义和不重要公式优先行内；
- 承担模型定义、核心推导、约束、结果的公式再使用独立编号；
- 统一使用 `\label{eq:...}` + `\eqref{eq:...}`；
- 向量、矩阵统一用粗体；
- 单位用正体；
- 不把几十行连续推导堆在正文中。

复杂模型建立后建议增加“模型汇总”。直接写：

```text
综合上述定义，模型为
[min / max / lex min]
subject to
[核心约束]
```

不要写“目标函数直接写为”“使用某函数表示为”等口语引导。模型汇总应能独立看清决策变量、目标和约束。

## 8. 表格

统一使用三线表，不画纵向网格线。建议样式：

```tex
\begin{table}[!htbp]
\centering
\caption{表题}
\label{tab:xxx}
\begin{tabular}{cccc}
\toprule
\rowcolor{CumcmLightBlue}
列1 & 列2 & 列3 & 列4 \\
\midrule
... \\
\bottomrule
\end{tabular}
\end{table}
```

规范：

- 表题由 LaTeX 统一生成；
- 表头可用 `CumcmLightBlue` 浅蓝底；
- 单位尽量放在表头或变量定义中；
- 小数位与数据精度和结论一致；
- 一张表只承担一个信息任务；
- 双列表过窄时优先局部增加 `\tabcolsep`；多列表接近正文宽度时再考虑 `tabular*`/`resizebox`，避免破坏彩色表头；
- 符号表 `tabularx` 可局部增加 `\extrarowheight`，模板已给示例。

## 9. 插图与 Origin 图规范

所有正文图放：

```text
modules/<模块>/figures/
```

Origin、Excel、AGX 等可编辑源放：

```text
modules/<模块>/figures/editable/
```

论文视觉尺寸：

- 单图：`0.44\textwidth`；
- 两个独立小图并排：每个约 `0.44\textwidth`，总宽约 `0.88\textwidth`；
- 已在 Origin 中合成的双面板图：整张 `0.88\textwidth`；
- 总体流程图：约 `1.0\textwidth`；
- 机理示意图：通常 `0.70\textwidth`，复杂时可放宽。

模板宏：

```tex
\FigureSingleWidth
\FigureDoubleWidth
\FigureFlowWidth
\FigureMechanismWidth
```

每张正式图和表都必须在正文中被 `\ref` 引用，并解释“说明了什么”。如果图表与文字完全重复，删去其一或压缩文字。

若指标相差多个数量级、零值较多且需要保留单位和精确值，优先用表格，不强行画统一坐标图。

## 10. 浮动体与分页

总体流程图可用 `[H]` 保持位置；普通结果图优先 `[!htbp]`。若 `[H]` 图后紧跟“标题 + 长段落 + 多行 align”，可能造成页底大面积空白，应优先拆分公式块或缩短文字，而不是先缩小图。

`FloatBarrier` 用于明确章节边界，不要为了填版面随意删除。

## 11. 伪代码

伪代码使用 `algorithm2e`：

- 输入 / 初始化 / 输出使用中文；
- `for / if / while` 等控制关键字可保留统一英文形式；
- 动作和判断条件用简洁中文；
- 关键循环、可行性检查、停止条件完整保留；
- 不直接复制 Python 语法；
- 不把整段伪代码全部翻成自然语言。

算法小节不能只有一大段文字。至少先给 1--2 个决定搜索/更新规则的数学量（排序键、接受准则、约化成本等），再接伪代码。

## 12. 代码附录

按当年提交规则二选一：

**模式 A：另交程序文件。** 附录列“文件 + 功能”，必要时放短代码片段。

**模式 B：只交 PDF 且代码页不计正文页数。** 用 `\lstinputlisting` 直接收入每问最终核心程序，可以完整展示求解、场景分析和约束检验代码；不要手工复制，以免与正式代码真源不同。

模板 `modules/80_appendix/paper/appendix.tex` 已给两种模式。

## 13. 模型评价

建议保留：模型总结、模型优点、模型局限与改进方向。每一点必须针对实际处理，不写“模型精度高、适用范围广”等无法由结果支撑的套话。

## 14. 参考文献

- 正式论文建议至少10篇，英文不少于3篇；
- 新方法、参数、数据来源优先引用原始论文/官方资料；
- 引用必须真正支持对应句子；
- 参考文献另起一页；
- 15条左右时默认可用 `\footnotesize` 和较小条目间距争取一页排完，但不能压缩到难以阅读。

## 15. AI 使用报告

只说明 AI 参与了哪些环节、团队如何复核、正式结果从哪里计算得到。不要写“与范文差多少”“为了贴合答案”等内部答辩式语言。

## 16. 修改格式前的责任边界

- 字体、页边距、标题、目录、图表宏、公共宏包：`feature/paper-shell`；
- 摘要：`feature/abstract`；
- 问题重述：`feature/restatement`；
- 符号说明：`feature/notation`；
- 模型假设：`feature/assumptions`；
- Q1/Q2/Q3/Q4：各自分支；
- 模型评价、参考文献、附录、AI报告：各自独立分支。

AI若认为“整个论文格式需要调整”，先说明应改 `paper-shell`，不能在 Q1/Q2 章节里重定义字体或标题。

## 17. 开赛后最小改法

1. 改 `paper/title.tex`；
2. 按题目数运行 `scripts/set_questions.py`；
3. 各章节直接替换示例文字；
4. Q1 保留有用的小节、公式、表格、伪代码和图环境，删掉不适用部分；
5. Q2/Q3 从一级标题开始补正文；
6. 图表按固定资源路径替换；
7. 不重新设计字体、行距和编号，除非官方模板变化；
8. 终稿前按 `docs/FINAL_PAPER_CHECKLIST.md` 逐项检查，并运行一键 preview。
