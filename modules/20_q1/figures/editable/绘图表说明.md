本次按实际导入反馈返工：传热—固化图拆为两份表，敏感性表采用两组 X–Y–Y。CSV 均为 UTF-8 BOM；保留源数值精度，不重算模型、不做网格插值。DSC 数据表和用户已制作的图、OPJU 不改动。

## 温度场矩阵.csv

- 文件范围 A1:AH92；温度矩阵为 B2:AH92，共 91 行 × 33 列。
- 首行 B1:AH1 仅为时间数字：0、10、…、310、311.25，单位 s。
- 首列 A2:A92 仅为距贴身侧位置数字，范围 0–1.4，单位 mm。
- A1 留空；内部全为温度数值，单位 ℃。无文字列头、补齐空列或辅助曲线。

Origin 导入到**工作表**，将全部 92 行作为数据（标题行数设为 0，数据从第 1 行开始），不要把首行数字吃进“长名称”。选中 A1:AH92，选择“绘图 → 等高线 → 热图（Heatmap）”。虚拟矩阵设置：

| 设置 | 取值 |
|---|---|
| 数据布局 | X 跨列（X across columns） |
| X 值 | 选区第一行 |
| Y 值 | 选区第一列 |
| X 轴标题 | 时间（s） |
| Y 轴标题 | 距贴身侧位置（mm） |
| 色标标题 | 温度（℃） |

直接使用该矩阵，不再转置或重新整理。空间坐标分层非等距，最后两个时间点相差 1.25 s，不能按普通 Matrixbook 的起止值强行等距映射。Origin 虚拟矩阵支持有序非等距坐标。参见 [Origin 虚拟矩阵说明](https://docs.originlab.com/origin-help/plot-3d-contour-virtmat/) 和 [热图说明](https://docs.originlab.com/origin-help/heat_map/)。

若已经导入且时间数字落在“长名称”行，X 值应改选“列标签 → 长名称”，Y 仍取第一列；此时不能把第一行温度数据当成 X。两种导入布局只能选择与实际工作表对应的一种。
